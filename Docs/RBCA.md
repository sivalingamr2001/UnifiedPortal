# JAN RBAC Schema Reference
### MySQL (development) + Oracle (production migration) — DDL + CRUD

This document contains the complete RBAC schema for the JAN application:
- 8 tables: Modules → Menus → Role-Menu-Permissions, Users, Roles, User Access Rights, Audit Log, Sessions
- Full **CREATE** scripts for **MySQL** and **Oracle**
- Full **SELECT / INSERT / UPDATE / DELETE** scripts for every table, in both dialects

Table build order (respects FK dependencies): `JAN_ROLES` → `JAN_MODULES` → `JAN_MENUS` → `JAN_USER_MASTER` → `JAN_ROLE_MENU` → `JAN_USER_ACCESS_RIGHTS` → `JAN_AUDIT_LOG` → `JAN_USER_SESSIONS`

```sql
-- DELETE (hard delete — only if no dependent rows)
```

## 3. JAN_MENUS

```sql
    MENU_ID         INT AUTO_INCREMENT PRIMARY KEY,
    MENU_CODE       VARCHAR(10)   NOT NULL,
    MENU_NAME       VARCHAR(100)  NOT NULL,
    DISPLAY_NAME    VARCHAR(100)  NOT NULL,
    MODULE_ID       INT           NOT NULL,
    PARENT_MENU_ID  INT,
    MENU_TYPE       VARCHAR(20)   NOT NULL,
    NATURE          VARCHAR(20)   NOT NULL,
    SORT_ORDER      SMALLINT,

    CREATED_BY      VARCHAR(50)   NOT NULL,
    CREATED_DATE    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    MODIFIED_BY     VARCHAR(50),
    MODIFIED_DATE   DATETIME,
    MENU_PATH       VARCHAR(100),
    MENU_ICON       VARCHAR(100),
    CONSTRAINT UQ_JAN_MENUS_CODE UNIQUE (MENU_CODE),
```

```sql
JOIN JAN_MENUS mn   ON mn.MENU_ID = rm.MENU_ID
JOIN JAN_MODULES md ON md.MODULE_ID = mn.MODULE_ID
WHERE rm.ROLE_ID = :role_id
  AND rm.PERM_VIEW = 'Y'
  AND mn.STATUS = 'ACTIVE'
  AND md.STATUS = 'ACTIVE'
ORDER BY md.SORT_ORDER, mn.PARENT_MENU_ID NULLS FIRST, mn.SORT_ORDER;
```

**Frontend flow:**
1. Group results by `MODULE_ID` → build sidebar sections in `MODULE_SORT` order.
2. Within each module, build the menu tree from `PARENT_MENU_ID` (null = top-level) ordered by `MENU_SORT`.
3. When a screen loads, look up its row by `MENU_ID` → toggle Add/Edit/Delete/Export/Approve buttons from the `PERM_*` flags.
4. Split `RESTRICTED_COLUMNS` (CSV) and hide those fields/grid columns.
5. Always re-check the same permission server-side in the API layer before executing the action — client-side hiding is UX only, not security.

## 10. Migration Notes: MySQL → Oracle

| MySQL | Oracle | Notes |
|---|---|---|
| `INT AUTO_INCREMENT` | `NUMBER(10)` + `SEQUENCE` + `BEFORE INSERT` trigger | Oracle 12c+ can use `GENERATED BY DEFAULT AS IDENTITY` instead of sequence+trigger if you're on 12c or later — simpler, shown as an alternative below. |
| `DATETIME` / `TIMESTAMP` | `DATE` (or `TIMESTAMP` if sub-second precision needed) | Oracle `DATE` already stores time down to the second. |
| `VARCHAR(n)` | `VARCHAR2(n)` | Direct rename. |
| `LONGTEXT` | `CLOB` | Direct mapping for audit OLD_VALUE/NEW_VALUE. |
| `DECIMAL(p,s)` | `NUMBER(p,s)` | Direct mapping. |
| `CHECK (... IN (...))` | Same syntax | Both support standard CHECK constraints. |
| `NOW()` | `SYSDATE` | Direct swap in scripts above. |
| `ON DUPLICATE KEY UPDATE` | `MERGE` | Already shown for `JAN_ROLE_MENU`. |
| `LIMIT n` | `FETCH FIRST n ROWS ONLY` | Already shown for `JAN_AUDIT_LOG`. |
| `DATE_ADD(x, INTERVAL n HOUR)` | `x + (n/24)` | Already shown for `JAN_USER_SESSIONS`. |
| `ENGINE=InnoDB` | N/A | Drop entirely — Oracle has no storage-engine clause. |

### Oracle 12c+ alternative (IDENTITY column, no sequence/trigger needed)
```sql
-- Example for JAN_ROLES — apply the same pattern to the other 7 tables if on Oracle 12c+
CREATE TABLE JAN_ROLES (
    ROLE_ID   NUMBER(10) GENERATED BY DEFAULT AS IDENTITY (START WITH 1 INCREMENT BY 1) NOT NULL,
    ROLE_CODE VARCHAR2(10) NOT NULL,
    -- ... remaining columns unchanged
    CONSTRAINT PK_JAN_ROLES PRIMARY KEY (ROLE_ID)
);
-- No sequence, no trigger required — INSERT without specifying ROLE_ID.
```

### Migration checklist
1. Create Oracle tables in dependency order (see top of this document).
2. Create sequences (or use IDENTITY columns).
3. Create triggers (skip if using IDENTITY columns).
4. Export MySQL data (`mysqldump --no-create-info --compatible=oracle`, or use a tool like AWS SCT / Ora2Pg for a clean automated conversion).
5. Load data — insert in dependency order: ROLES → MODULES → MENUS → USER_MASTER → ROLE_MENU → USER_ACCESS_RIGHTS → AUDIT_LOG → USER_SESSIONS.
6. Reset sequences to `MAX(ID)+1` after bulk load: `ALTER SEQUENCE JAN_SEQ_JAN_ROLES RESTART START WITH <max+1>` (or use `SELECT JAN_SEQ_x.NEXTVAL` loop trick pre-12c).
7. Verify FK integrity and rebuild indexes.
